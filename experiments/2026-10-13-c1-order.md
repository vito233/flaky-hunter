## 做了什么

- `runner.py`：新增顺序执行原语 —— `build_sequence_script`（按给定节点 ID
  顺序单进程跑一组测试）+ `run_sequence` + JUnit XML → 输入节点 ID 的
  逐测试判定映射；`--collect-only` 加 `-p no:randomly`（顺序可控的地基）
- `detect_order.py`：OD 家族猎手。多顺序扫描（默认/反向/定种子随机）→
  victim 候选（某顺序挂 ∧ 单独跑全过）→ 前缀二分 → 保序 ddmin 最小
  polluter 集合 → 三条件验证（复现挂 / victim 单独过 / polluter 单独过）
- `metrics.py`：Prediction 增 mode/polluters/orders_tried/minimized 字段；
  `combine_modes()` 合并口径（replay ∪ order，任一报警即报警）
- `experiments/run_order_eval.py`：与 run_eval 同一评测集（19 正 + N1 负 ×2），
  产出 results_order.csv / metrics_order.json / metrics_combined.json
- 单测 160 个全绿（新增 44 个：ddmin 全表、二分边界、判定规则、
  FakeRunner 接线含"顺序没跑完"路径）；ruff 三过

三个值得在面试里讲的结论：

1. **replay 的 8 条 FN 全部变成 TP，一条不多一条不少**：顺序模式独立
   OD-Vic 召回 12/12（含 replay 已抓的 4 条），合并后 19/20（唯一漏网
   是 NOD 型 test_deco_timeout，见上方审计更正）。
   两个模式抓不同机制（固定顺序翻转 vs 套装顺序依赖），合并口径
   F1 0.974 对基线 0.755 —— 检测器的完整形态是双模式并联。
2. **归因做到了测试级**：每个 victim 都挖出了最小 polluter 集合
   （ddmin 全部收敛）。mdutils 8 条 victim 的 polluter 全是同一条 ——
   `tests/test_fileutils/test_fileutils.py::TestMarkdownFile::test_append_end`
   （或该类里任何一条 chdir 测试）：`os.chdir(临时目录)` + TemporaryDirectory
   退出删目录 → 进程 CWD 没了 → 之后所有相对路径操作 FileNotFoundError。
   失败签名（证据日志里可查）：`open('Test_file.md', 'w+')` →
   `FileNotFoundError: [Errno 2] No such file or directory`。
   yamicache 的 OD-Vic（test_noclass.py::test_main）polluter 是
   test_object_list；python-fs 的 polluter 是 test_mkdir_recursive
   （它自己还是条 NIO —— 污染者本身也是 flaky）。
3. **顺序扫描在评测集外抓到 11 条 victim**（yamicache 2 条、
   freezegun 8 条、Pyro5 1 条）。
   **2026-10-13 深夜审计更正**：当时写成"IDoFT 没记录"是错的 ——
   对照 py-data.csv 全库，**10 条是 IDoFT 已记录**（同 SHA 同类别
   OD-Vic，阶段 A 抽样未进真值表而已），**真·未记录只有 Pyro5
   `test_daemon.py::TestDaemon::testHandshakeDenied` 1 条**（已列为
   IDoFT 提交候选）。10 条的价值 = 独立复现 + polluter 归因增强，
   不是新发现。详见 groundtruth-audit。

## 卡在哪 / 踩坑（全是面试素材）

1. **pytest-randomly 差点毁掉整个方案**：deps 里装着它，会在
   `pytest_collection_modifyitems` 里随机重排 —— 我们传什么顺序都被
   搅乱。修：所有顺序相关命令 `-p no:randomly`（含 --collect-only）。
   先验证了"pytest 按命令行节点 ID 顺序执行"才敢这么设计。
2. **JUnit XML 没有 file 属性**（实测 pytest 8.4.2）：只有 classname
   （点号路径，目录名重复也全带，如 tests.test_fileutils.test_fileutils
   .TestMarkdownFile）+ name。按输入节点反推期望值再匹配。
3. **XML 区域为空 ≠ XML 损坏**：freezegun 把 pytest 搞崩时标记齐全、
   XML 空 —— 给了独立 reason（XML_EMPTY），log_tail 里留完整堆栈。
   教训：顺序扫描会被被测项目的 flaky 机制本身打到，熔断/留痕/跳过，
   不许冒充"全过"。
4. **victim 判定必须"单独跑全过"兜底**：regex4ocr 有 2 条套装里挂的
   测试，单独跑 0过/10挂（本来就是坏的）—— 不是顺序依赖，跳过。
   没有这一关就会把坏测试当 OD-Vic 报。
